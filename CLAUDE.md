## Default approach when asked to build a new site here (read this first)

Every tool listed in this file — skills and libraries both — is available. The point of this section is to make sure they're all *considered*, not that they're all *used*. Stacking every library onto one site is not what makes it look premium; the `web_cheatcodes.pdf` someone sent for this repo ends with the line that actually matters: *"Good design + typography + spacing + 2–3 intentional animations > 50 random effects."* Take that literally.

1. **Direction before tools.** Start with `design-taste-frontend` (plus `brandkit` or `ui-ux-pro-max` if there's no direction yet) to get an actual point of view for *this* project — audience, tone, what "premium" means here — before reaching for any library. A restrained static page with 2–3 intentional touches beats one carrying every tool in this file.
2. **Plain HTML/CSS/JS is the default.** Only add a bundler (Vite + React, per `book-site-react/`) when a specific chosen effect genuinely needs one (`react-bits`, `@react-three/fiber`, Framer Motion). Converting a project to React is a real architecture decision, not a tooling add — ask first, the way `book-site-react/` only happened after being asked directly.
3. **Match the tool to the project, don't stack them all in:**
   - *Landing/marketing page* → direction skill, maybe `Lenis` + GSAP `ScrollTrigger` for scroll feel, then `web-design-guidelines` + `playwright-cli` to verify. No 3D unless there's an actual 3D subject.
   - *Portfolio / resume / academic work* → restraint over spectacle: clean typography, fast load, accessible. This is `emil-apple-design`'s "feedback, spatial consistency, restraint" and the PDF's "don't animate everything," applied hardest — a recruiter or professor isn't the audience for a WebGL showcase (this is why `Iman_Kasim_Portfolio.html` stayed plain HTML).
   - *Deliberately cinematic/showcase project* (like `book-site-react/`) → the fuller stack is fair game, but still pick 2–3 signature moments, not every effect in the PDF's "Premium Website Effects" list. This repo's example used exactly three: one hero starfield, one headline reveal, one metallic-text accent. **A genuinely new "premium 3D scroll-driven site" request** (as opposed to a variant/edit of an existing project) should invoke the `premium-3d-website` skill — it's the standing decision system for that exact request class (stack rules, five-act structure, camera choreography, verification), built specifically so this doesn't need re-deriving from scratch each time one comes in.
   - *3D* (Three.js / React Three Fiber / Drei / Spline, or **`ogl`**) is only for a project with an actual 3D subject — a product, a model, a spatial concept. Bolting 3D onto a page with nothing 3D to show is the "don't load huge libraries for tiny effects" anti-pattern the PDF itself names. Which library: see the hard-won note in the `red-rising-archive` section below — `@react-three/fiber`/three.js did not render reliably in this container even when every internal check (render calls, triangle counts, WebGL context) said it should have; `ogl` (already a dependency via `book-site-react`'s `Particles`) did, immediately and consistently, at roughly a third of the bundle weight. Default to `ogl` for new 3D work here unless there's a specific reason to need three.js's ecosystem (e.g. a specific drei helper with no ogl equivalent).
4. **Verify before calling it premium.** `web-design-guidelines` audit + `playwright-cli` screenshots at 320/375/1440px + an actual no-JS and reduced-motion check — not a skipped afterthought. Two real bugs this repo has already hit were caught exactly this way: a no-JS nav bug in the original static book-site build, and `book-site-react/`'s opacity-gated content going invisible under a full-page screenshot. Something that breaks under a screenshot tool or with JS off isn't premium, it's fragile.
5. **Say plainly whether you're replacing something or adding something new.** When a build like `book-site-react/` starts as a variant of an existing page, say explicitly whether the old version stays live alongside it or gets replaced — "I converted X" is ambiguous between those two and caused real confusion here (see git history around the `book-site/` removal). Default to asking which is wanted before assuming either.

Full tool inventory — what each one is for, and its real caveats — is below.

## book-site-react (React + Vite build)

Source lives in `book-site-react/`; `node_modules/` and `dist/` are gitignored — **the build output is not committed**. It's built and deployed by `.github/workflows/pages.yml`, which also assembles the plain files (root `index.html`, `Iman_Kasim_Portfolio.html`) and `red-rising-archive/`'s build into the same Pages artifact. This replaced an earlier plain-static version at `book-site/`, which was removed once this one superseded it; don't recreate `book-site/` unless asked. Deployment is on **GitHub Actions** (Settings → Pages → Source), already switched — GitHub Pages allows only one deployment source per repo, so this superseded the old "Deploy from a branch" method entirely, for the whole site, not just this project.

Libraries used and why: **Lenis** (smooth scroll) + **GSAP `ScrollTrigger`** (scroll-based reveal), wired via the standard `lenis.on('scroll', ScrollTrigger.update)` + `gsap.ticker` integration in `src/main.jsx`. Three **react-bits** components are vendored into `src/components/` (not npm-installed — that's how react-bits ships): `Particles` (WebGL starfield, `ogl` dependency), `SplitText` (GSAP-driven headline reveal), `ShinyText` (`motion` dependency, metallic sheen on the byline). License is MIT + Commons Clause (`src/components/REACT-BITS-LICENSE.md`) — fine to use in this site, not fine to resell/redistribute the components themselves.

One real trade-off from switching to client-rendered React, not swept under the rug: there's no server-side rendering, so with JavaScript disabled the page shows only a plain `<noscript>` message asking the visitor to enable JavaScript — the original static build (now removed) stayed fully readable with JS off; this one doesn't. That regression was accepted knowingly when the static version was retired in favor of this one, not an oversight.

One bug found and fixed during QA, worth knowing if this pattern gets reused: the scroll-reveal (`src/components/Reveal.jsx`) originally hid content at `opacity: 0` until a real scroll event fired it — which meant a full-page screenshot tool (including `playwright-cli --full-page`, used for this repo's own QA), print/PDF export, or any partial JS failure left everything below the hero permanently invisible. Fixed by never touching opacity: only the lift `transform` animates, so content defaults to fully visible and readable even if the scroll trigger never fires.

Environment note: this container's Chromium needs `--no-sandbox` to launch as root — already set in `.playwright/cli.config.json`'s `launchOptions.args`; don't remove it.

## red-rising-archive (React + Vite + OGL build)

A much deeper Red Rising fan build than `book-site-react/` — full character dossiers, lore/world encyclopedia, a filterable quote vault, a spoiler-level system, and a scroll-scrubbed 3D book carousel — built from a 40-section brief. Deliberately kept as a **separate** project from `book-site-react/`, not a replacement, per an explicit yes/no asked before building it (see point 5 above) — don't merge or remove either without asking again. Same deployment mechanism as `book-site-react/`: source in `red-rising-archive/`, `node_modules/`/`dist/` gitignored, built and assembled by the same `.github/workflows/pages.yml`.

**Fact-checking discipline** (the brief itself demanded this): before writing any character/lore/quote content, real claims were checked against actual sources (Red Rising Wiki, search) rather than trusted from the brief or from memory — house mottos and sigils (Augustus/lion, Bellona/eagle, Telemanus/fox), Pax au Augustus's parentage, character epithets (Diomedes/Storm Knight, Atlas/Fear Knight, Apollonius/Minotaur of Mars), and the actual wording/speaker of quotes (Eo, not Darrow, says "Then you must live for more" — the brief's own "Words That Stay" list had this misattributed). Where a claim couldn't be verified with confidence (some of the brief's "Howler's Creed" phrases, some X/social handles), it's labeled as fan-composed/unverified in `src/data/*.js` and the UI rather than asserted as canon — see `design.md` and the data files' own comments for exactly what's verified vs. not. Extend this discipline to any new content added here, not just the initial build.

**The one real engineering lesson worth carrying forward, because it cost significant effort to find**: the 3D book carousel was first built with `@react-three/fiber` + `three.js` + `@react-three/drei`. It failed to render *at all* in this container — a solid black canvas — despite every internal check passing (correct WebGL context, correct render-call/triangle counts via `renderer.info`, correct camera/geometry math, zero console errors). Chased through several false leads (alpha compositing, tone mapping, `powerPreference`, GSAP's `pin: true` DOM-mutation racing with React Three Fiber's `ResizeObserver`-based canvas sizing — switching to CSS `position: sticky` fixed a real, separate layout bug along the way but not the blank-canvas issue). The fix was replacing three.js/R3F entirely with **`ogl`** (already proven working in this exact container via `book-site-react`'s `Particles` component) — it rendered correctly on the very first try, with no scroll-dependent flakiness, and cut the bundle from 413KB to 145KB gzip in the process. If a future 3D need shows the same "renders internally correct, shows nothing on screen" symptom in this container, don't keep debugging three.js — switch to `ogl` first and confirm, before spending more time on the heavier library.

**Update, a later session (do not silently trust the paragraph above as still true without reading this):** re-tested basic `@react-three/fiber` rendering in this exact class of container, prompted by the user wanting to reconsider three.js for a future 3D build. Two isolated smoke tests (a bare R3F `Canvas` with a spinning mesh, and the same wrapped in a real GSAP `ScrollTrigger` `pin: true` section, the specific scenario named above as a suspected cause) both rendered correctly and kept animating through the pin, verified with real `playwright-cli` screenshots showing the mesh in two different rotations. That directly contradicts "failed to render at all... blank canvas" as a still-true blanket statement. What this does and doesn't prove:
- It's real evidence the *fundamental* R3F-in-this-container and pin/ResizeObserver-race failure modes above are not currently reproducing, at least in isolation and at least in whatever container instance ran that test — sessions may not all share identical underlying container images/GPU drivers, so "fixed forever" cannot be claimed from one passing re-test.
- It is **not** a re-test of the original, more complex failing scene (the actual book slabs used canvas-texture materials, specific tone mapping, `powerPreference`, and `@react-three/drei` helpers, none of which this smoke test included) — so it does not prove the original scene would now render, only that the simplest version of the suspected mechanism no longer reproduces.
- Conclusion: don't treat `ogl` as mandatory-by-fiat anymore, but don't switch `red-rising-archive` back to three.js/R3F off the strength of this smoke test either. If a future 3D build wants three.js/R3F, re-verify with something closer to the real scene first (real materials/textures, real Drei helpers if used) and only then decide — the cost of being wrong here is the same multi-hour debugging slog documented above, not a small revert.

**Lessons from the first round of user feedback after shipping** (background was flat, scroll felt jittery, books section wasn't usable) — also the round where `design-taste-frontend` should have been run *during* the build and wasn't; it was only actually invoked after the user caught the gap directly. Don't repeat that: run the direction skill before implementation, not as a post-hoc audit.
- **Flat background**: a solid `--charcoal`/`--void` background reads as boring regardless of how good the typography is. Fixed with a fixed, `z-index:0`, `aria-hidden` `.ambient` layer of several low-opacity (8-16%) `radial-gradient`s in the existing red/gold palette, plus a `.vignette` inset box-shadow, sitting behind all content; `section.alt` backgrounds were changed from a solid color to a semi-transparent gradient so the ambient glow actually bleeds through instead of being fully occluded.
- **Scroll jitter root cause was not the 3D rendering** — it was calling `setState` on every `ScrollTrigger` `onUpdate` tick (which fires every animation frame while scrubbing), re-rendering the caption and nav buttons dozens of times a second. `design-taste-frontend` Section 5.D calls this out explicitly (don't track continuous scroll values in `useState`). Fix: keep the raw progress in a `useRef` for the render loop, and only call `setState` when the *rounded* index actually changes. Also pause the OGL rAF loop via `IntersectionObserver` when the canvas host isn't visible, since it's sticky-pinned and only on-screen for part of a long scroll host.
- **Fixed-position elements need their real measured height, not a guessed pixel offset**, when something else needs to anchor above them. `SpoilerBar` is fixed to the viewport bottom and wraps to two lines on narrow viewports, so its height isn't constant; an earlier layout used a hardcoded offset that went negative and clipped the books-carousel scrub dots off-screen with no console error. Fixed by measuring the bar's real `offsetHeight` via `ResizeObserver`, writing it to a `--spoiler-bar-h` CSS custom property, and having anything anchored above it (`.book-caption`) reference that variable in a `calc()`.
- A carousel driven only by scroll scrub with no other affordance is not "user friendly" by itself: added prev/next arrow buttons and clickable/keyboard-navigable (arrow-key) scrub dots that jump via the shared Lenis instance (exposed as `window.__lenis` in `main.jsx`) rather than raw `window.scrollTo`, so programmatic jumps feel the same as manual scroll.
- `emil-review-animations` has `disable-model-invocation` set — it cannot be invoked via the Skill tool by Claude, even to help diagnose a motion complaint. It's reserved for the user to run directly as `/emil-review-animations`. Diagnose motion issues by direct code inspection instead of trying to route around this.

**A `web-design-guidelines` audit run against this project after the round above found four more real, confirmed bugs** — not the same jitter/background complaints, a genuinely separate pass, which is the point of actually running the audit rather than re-inspecting the same three named issues:
- `Reveal.jsx`'s GSAP scroll-reveal tween ran unconditionally. The global CSS `prefers-reduced-motion` rule (`index.css`) only zeroes CSS `transition`/`animation` durations, it does nothing to a JS-driven `gsap.fromTo` tween, so every reveal on the page ignored the OS-level reduced-motion setting. Fixed by checking `window.matchMedia('(prefers-reduced-motion: reduce)').matches` inside the `useGSAP` callback and skipping the tween entirely when true (content is written at its resting position, so it's just immediately visible, not visible-then-jump).
- The exact same fixed-bottom-bar-covers-content bug as the books-carousel fix, just in a different spot: the page footer's `padding-bottom` (40px) was less than `--spoiler-bar-h`, so the fixed `SpoilerBar` permanently covered the footer's last links and copyright line on every page load, not just under scroll. Same fix pattern: `padding-bottom: calc(var(--space-4) + var(--spoiler-bar-h))`.
- The `CharacterDossier` modal (`role="dialog" aria-modal="true"`) never moved focus into itself on open or restored it on close, and didn't lock body scroll — a real, not cosmetic, gap for keyboard/screen-reader users. Fixed with a `tabIndex={-1}` ref that gets focused on mount, `document.body.style.overflow = 'hidden'` while open, and restoring focus to `document.activeElement` from the moment before opening, all in the same `useEffect`/cleanup.
- No `color-scheme: dark` on `:root` (native scrollbar/form-control chrome was defaulting to light, wrong against an all-dark site) and no `<meta name="theme-color">` — both one-line fixes.

Verified all four live via `playwright-cli` (not just "the build succeeded"): screenshots confirmed the ambient background renders and the footer clears the spoiler bar at mobile width; `document.activeElement` was checked via `eval` before/after opening and Escaping the dossier modal to confirm the focus move and restore actually happen, not just that the code looks right.

**A ground-up redesign round, prompted by a generic "premium 3D website" toolkit brief (Next.js + Tailwind + shadcn/ui + three.js/R3F + Motion) that conflicted with this project's own already-proven stack.** Two real conflicts were surfaced and the user confirmed the resolution before any code changed: (1) the brief's required three.js/R3F/Drei is the exact combination this repo already spent real debugging effort proving broken in this container (see the engineering-lesson paragraph above) — staying on `ogl` was non-negotiable, not a style preference; (2) Next.js buys SSR/routing/API routes, none of which apply to a static GitHub Pages build, so migrating bundlers had no stated benefit against a real cost. The user chose: keep Vite + React + `ogl`, and treat this as a full rewrite of the design/architecture (not the underlying stack), reusing the already fact-checked content data rather than re-deriving facts that hadn't changed.

Ran `design-taste-frontend` for direction *before* touching code this time (the opposite of the first round's mistake). Its mechanical Pre-Flight Check caught a real, concrete anti-pattern this site had shipped with since the original build: **every one of the ~13 sections carried an "eyebrow" label** (`A PERSONAL FAN ARCHIVE`, `THE SAGA`, `THE QUOTE VAULT`, ...). The skill's rule caps this at 1 per 3 sections. Fixed by removing all of them except Hero's (1 of 13, well under the cap) — this is a structural fix, not a style opinion the skill happens to prefer.

Three signature moments were built (per the skill's own "2-3 intentional, not 50 effects" restraint rule, applied on top of the source PDF's own "better art direction, not more effects" section, which for once agreed):
1. **Real camera choreography on the existing `ogl` book carousel** (`SixBooksScroll.jsx`), replacing "static camera, spinning ring of books" with distance/height interpolated off scroll progress: a close-up push-in on the first book, an orbiting plateau through the middle five, and a pulled-back wide shot at the finale revealing the whole ring. Distance-only (no fov changes) to keep it cheap and avoid re-introducing any risk around `ogl`'s camera/perspective calls. Verified live by scrolling to specific progress points and screenshotting: book I fills most of the frame at the start, three books are visible at a smaller scale at the end.
2. **Five-act structure** (`ActDivider.jsx`) replacing the flat section list: Arrival / Revelation / Exploration / Immersion / Finale, connected by one full-bleed editorial line each (not a literal "Act II" label — the taste skill separately bans generic stage/phase numbering as an AI tell, so the source PDF's literal act-naming was adapted rather than followed verbatim). Ambient tint shifts slightly between acts without ever breaking the page's single locked dark theme.
3. **Moments section rebuilt as a vertical timeline** instead of another bordered-card grid, specifically because My Ten / Fan Art / Buy already use that grid pattern and the taste skill's Section-Layout-Repetition rule caps how many sections can share one layout family.

What this round deliberately did *not* do: re-verify the already fact-checked character/lore/quote data (no new claims were made, so there was nothing to re-check), and does not use `impeccable`'s automated detector (still reference-content-only, see below) or `image-to-code`/`imagegen-*` (no image-generation tool connected in this session).

## the-rising-archive (Next.js static export + ogl build)

A third Red Rising fan build, built from a large "THE RED RISING ARCHIVE" brief using the `premium-3d-website` skill. It is **new and sits alongside** `red-rising-archive/` and `book-site-react/`; the user explicitly chose that over replacing either one, so don't merge or remove any of the three without asking. Deployed by the same `pages.yml` from `the-rising-archive/out/` to `/Portfolio/the-rising-archive/` (`basePath` in `next.config.ts`). All seven branches of the brief's structure now exist: The Story, The People, The World (fourteen-Colors caste tower, five house dossiers with the Telemanus Table and the Raa genealogy, factions with the Howler roll call, Olympic Knights and a redacted Ascomanni file, a Solar System map, the Artifact Vault), The Ideas (six question pages, ending on `/what-survives/`), The Fandom (arguments, open questions, the Chorus, verified quotes, the archive's plates), The Author (plus Sons of Ares and official sources) and The Sealed File (Red God). It was first built in phases with a review stop after Phase 1. The user then asked for the rest in one pass, along with fixes for the Phase 1 gaps.

- **Why Next.js here and not Vite:** the user picked it. Static export gives this content-heavy archive per-route SSG, real metadata and JSON-LD, and full no-JS readability, which the Vite builds don't have. Before touching Next APIs, read `the-rising-archive/AGENTS.md`. This Next version has breaking changes: `params` is a Promise, and it uses `PageProps<"/route">`.
- **3D is `ogl`, and it rendered correctly the first time in this container** (planet, stars, dust, mine shaft). That matches the red-rising-archive lesson. Reduced motion and no-JS both get a composed CSS-planet frame instead of the canvas.
- **shadcn/ui is vendored** from the shadcn GitHub repo into `components/ui/`, because `ui.shadcn.com` returns 403 in this container. `cn()` in `lib/utils.ts` registers the custom type-scale names (`text-h1`, `text-lede`, ...) with tailwind-merge. Without that, a component default such as `DialogTitle`'s `text-lg` silently beats `text-h1`. This bug happened and was caught by screenshot.
- **Spoilers:** each content item carries the book it spoils. `SpoilerGate` is a native `<details>`, so it works with JS off. The reader's clearance (0-6) lives in a `useSyncExternalStore` store (`lib/clearanceStore.ts`) rather than setState-in-effect, which the Next ESLint config rejects. The People lens bar (`TenFaces`) falls back to each person's `early` readings ("as first met", safe at the clearance before their first book, same rule as `intro`) so first-time readers aren't met with ten sealed cards; Legacy never has an early reading. Names can spoil too: a person's `cover` (Mustang, The Jackal, Pax) replaces name and epithet below `cover.book` via `PersonName`/`shownAs`, and static text (page titles, alt, no-JS) always uses `safeAs`. An `intro` entry written as `{ text, book }` gets its own seal, for sentences that spoil the character's first book.
- **Imagery is generated here, with this repo's image skills, and the recipe is committed.** `scripts/art/` holds `scenes.mjs` + `kit.mjs` (33 level-2 three.js scenes: character relics, house seals, planets, vault artifacts, Rising scenes) and `books.py` (level-1 code-drawn book plates + the OG card). Output is WebP under `public/images/`, about 1 MB total. Level-3 (Cloudflare Flux) was the only real image model, and it was blocked by the network policy. Nothing depicts a character's face, and nothing reproduces published covers: plates are symbolic objects and seals, and the site labels them as "archive plates." Two engine gotchas, both found by looking at renders, not by a failing check:
  - This container's source-built headless-gl lacks `OES_texture_half_float`, so `addStudioEnvironment`'s PMREM env map silently renders **black**. Any `metalness: 1` material then comes out black. The first fix was satin metals, which looked like plastic. The current `kit.metal()` is real reflective metal. It injects an analytic studio environment (sky gradient, two softboxes, a red kicker) into `MeshStandardMaterial` via `onBeforeCompile`, and samples it along the reflection vector. No textures, no extensions, and it renders mirror-like gold and chrome here.
  - **Two "make it look illustrated" attempts were tested and rejected, so don't retry them blindly.** A scratchboard line-screen post-process was invisible at page size and a mechanical moiré-prone texture up close. Toon shading with ink outlines flattened the metal and read cheaper. Real illustration needs the level-3 diffusion model, which is still network-blocked. What actually improved weak plates was rebuilding the scene: the StarShell became a fogged hangar of silhouetted suits with a person for scale, the dreadnought became a close three-quarter hero shot, and the storm uses soft `puff()` sprites instead of solid spheres.
  - `THREE.LatheGeometry` normals face inward if the profile runs top-down; `kit.lathe()` reverses such profiles.
  - Also in `scenes.mjs`: `scene.add(x).rotation...` rotates the *scene*, because `add` returns the parent. That bug blew out a render once.
  - Level-1's `Design` takes radii as fractions of width and line widths in final pixels. Passing pixel radii fills the canvas.
- **`<Plate>`** (`components/archive/Plate.tsx`) wraps `next/image` and prefixes `NEXT_PUBLIC_BASE_PATH` itself: Next's docs say `next/image` does not add `basePath` to `src`.
- **Controls that need JS** (clearance, sound) carry `data-js-only` and are hidden by a `<noscript><style>` in the layout. **Clearance-reactive UI** (Howler roll call, Telemanus Table, Raa tree, Constellation) reads `useArchive().clearance`. Its no-JS state is always the safe clearance-0 view. Every sealed text passage is a native `<details>` (`SpoilerGate`, or `Redacted` for the intelligence-file look).
- **`<Spotlight>`** (`components/archive/Spotlight.tsx`) is the Apollonius card's hover, generalised at the user's request. A cursor-following light plus a colour wash, as a `mix-blend-screen` overlay, in `red`, `gold` or `rim` tone. It writes cursor position to CSS variables on `pointermove`, never to React state, and the lift is `motion-safe` only. It is used on most cards across the site. `FaceCard` has its own copy, keyed to each person's register, and Apollonius keeps a stronger version.
- **`<SealedNotice>`** answers "the site looks empty at low clearance". It is a fixed pill that counts `main details.spoiler:not([open])` and offers "Unseal this page" (opens them, and changes no stored clearance) or "Clearance". It is dismissible per page, and the footer has extra bottom padding so the pill never covers its last links.
- **Rosters:** the Howlers were expanded from the Red Rising Wiki's member category to twelve described members, plus eight "also on the roll" names with no claimed detail. Alexandar and Rhonna are flagged as lancers ("Pup One/Two"), not full Howlers. The Olympic Knights now list ten of the twelve titles plus the disputed Shadow Knight. Holders appear only where verified; the rest carry an Unknown stamp.
- **Fact-checking:** the same discipline as red-rising-archive applies. Because WebFetch to Fandom and Wikipedia is blocked here, claims were checked via WebSearch. Items the brief got wrong were corrected, not copied. Unverifiable items were either cut (for example, Vale ages) or placed behind a later spoiler gate. QA also caught two lines I had written myself that were unsupported: a claim that Darrow finished Ragnar, and "hidden blade" for Octavia. Both were rewritten to the verified facts. Keep checking new content the same way. The later round corrected the brief as well: Fatherhood's "Atlas → his children" is Atlas → Ajax (verified), and Romulus → Diomedes was added alongside it. The Howler's Chorus is labelled as reader discussion, not a poll, because no poll was found. The same round fixed errors in the older `red-rising-archive`, which the user asked for. Ragnar's death was dated to Golden Son; it is Morning Star. "Darrow and Cassius, Training" implied they trained together; Darrow trained under Lorn in secret. "The Storm God" described the Reaper myth; the Storm Gods are hidden war machines. The Color hierarchy was also missing Pink.

## attack-on-titan-archive (Next.js static export + ogl build)

A fourth fan build, an Attack on Titan archive, built from a large "ATTACK ON TITAN, PREMIUM 3D ARCHIVE" brief with the `premium-3d-website` skill. It is **new and sits alongside** the other three; nothing was replaced. Deployed by `pages.yml` to `/Portfolio/attack-on-titan-archive/`. **It is deliberately NOT linked from root `index.html` yet.** The user chose "deploy but don't link until finished", so the URL works but only people given it will find it. Add the landing-page link only when the user signs off on the finished site.

- **Phased on purpose, pushed straight to `main`** (the user asked for main, no branch/PR). Phase 1 = design system, the opening shot, and the archive index. The index lists all ten chapters (AOT-01 to AOT-10) in the brief's three acts; only The Wall is "Open", the rest carry a Sealed stamp until built (`lib/data/chapters.ts`, flip `open`).
- **Stack:** same as the-rising-archive (Next 16 static export, Tailwind v4, GSAP ScrollTrigger + Lenis, ogl). Read `attack-on-titan-archive/AGENTS.md` before touching Next APIs. The brief asked for three.js/R3F/Drei + Vercel; neither was used. Hosting is GitHub Pages like everything else, and ogl was chosen because it is this repo's proven path. No R3F smoke test was needed since R3F isn't in play.
- **The opening shot** (`components/three/`, modular: Sky / Ground / Wall / Town / Titan / Steam / Xray / choreography) is one continuous scroll-scrubbed camera: Wall close-up, rise over Shiganshina, a shadow crossing the fields, down onto the parapet while the Colossal-type Titan is revealed bottom-up by a clearing steam column, eye glints, flash, gate breach, title, then through the Wall as an x-ray, then out to the world. Units: 1 = 10 m (Wall 5, Titan ~6.2, verified 50 m / 60 m). Shadows are analytic (ring + capsule ray tests), no shadow maps.
- **The Titan is a raymarched SDF** inside a proxy box (`Titan.ts`), not meshes. Lessons, found by screenshot, so don't repeat them: merged ellipsoids read as a ball-jointed mannequin; sine-based muscle striation aliases into contour bands (use anisotropic noise); extra anatomy primitives (abs, neck cords) read as pipes and rings under rim light; a geometric cut-plane reveal looks like sliced sausage (reveal with a clearing steam column instead, and give steam a higher `renderOrder` than the body); close-up procedural faces fail, so the Titan is **backlit** (sun behind it), which makes it a silhouette with rim light, a grin arc of teeth and two eye glints. It is a generic flayed giant, not a copy of the anime's design.
- **Round 2 upgrades** (user asked to push the Titan and the outside world further): canon order (lightning strike, then steam, then a long shadow over the district, then the steam column clears; the kick is its own beat with a camera shake); the Titan moved to peer over the Wall and leans in; backlit translucency on its flesh (Barré-Brisebois/Bouchard fast SSS); a bird flock that scatters at the strike; displaced terrain with a river valley (`terrain.ts`, one height function written in GLSL and JS so trees and walking Titans sit on it); ~11k instanced conifers in one draw call; drifting cloud shadows; post chain (`Post.ts`: screen-space god rays after GPU Gems 3, FXAA-lite, vignette, grain, slight edge chromatic split).
- **Two engine bugs found by screenshot this round, both silent:** (1) ogl `RenderTarget` uses a **16-bit depth buffer** unless `stencil: true` (which gives 24-bit). Over a 3 km scene that z-fought the Wall into stripes and hid the land behind the sky. Keep `stencil: true` on any scene target. (2) ogl uploads vertex buffers at construction; rewriting `attributes.position.data` afterwards needs `needsUpdate = true`, or the GPU keeps the old mesh (the ground collapsed to a line).
- **Personnel portraits** (`scripts/portraits/treat.py`, Pillow): each character becomes a different recovered artifact over one shared base (site-palette duotone, halftone, grain): Eren burned print, Armin map-clipped, Erwin mount board, Connie/Sasha snapshots, Hange notebook page, Annie frosted, Grisha basement photograph, Gabi/Zeke Marleyan posters, Ymir water-damaged, Historia banknote engraving. Captions carry only verified facts. Crops also remove subtitles, a Reddit credit and a watermark from the sources. Fonts are the site's own (OFL) in `scripts/portraits/fonts/`. Output: `public/images/personnel/*.webp`, transparent, 50-160 KB. Shown on `/soldiers/` and each dossier since Phase 2. Sources and credits live in `lib/data/portraits.ts`: all anime screenshots except Levi, which is fan art by an unidentified artist, used because the user decided to after being told the artist's permission was missing; it must stay credited as fan art. The user confirmed page 6 of their upload is Reiner and page 12 is Grisha.
- **Phase 2 (AOT-02 The Fall, AOT-03 The Soldiers), now Open in the index.** `/the-fall/` is a 845-847 ledger (sticky year column), a to-scale map of the three Walls (`WallsMap.tsx`, radii 250/380/480 km from the story's own figures, districts marked not-to-scale, the lost ring hatched) and the reclamation figures (250,000 sent, about 100 back, a fifth of the population). Its hero is a frame rendered from the opening scene (`public/images/fall-845.webp`, p=0.425 via a frame script: hide the DOM, scroll the pinned section, screenshot). `/soldiers/` is a filterable desk of the 16 portrait artifacts (varied spans, not a card grid; filter buttons are `data-js-only`, no-JS shows all files); `/soldiers/[slug]/` is the personnel file: portrait plus credit, a paper field sheet, then the brief's six layers. Status, Transformation and Legacy are sealed in native `<details>` (`Sealed.tsx`, `onPaper` variant for labels on paper) because they spoil the ending. Dossier text is in `lib/data/people.ts`; every line was checked, and details that couldn't be pinned down (exact birth years, some hometown names) were left out rather than guessed. Plain `<img>` with width/height is deliberate (static export, unoptimized; the lint rule is off with a comment in `eslint.config.mjs`).
- **No-JS / reduced motion:** the static hero uses real frames rendered from the scene (`public/images/opening-845*.webp`, landscape + portrait, made by screenshotting the canvas at p=0.705 with the DOM hidden; regenerate the same way if the scene changes). Reduced motion renders a single still WebGL frame at the same point.
- **Sound** (`lib/audio/engine.ts`) is synthesized wind + distant birds + an arrival crack, off until the visitor clicks the toggle.
- **Character images:** the user will supply screenshots for the personnel files. The plan agreed with them: raw files go in the gitignored `portraits-src/`, a build-time Pillow script applies a per-character archival treatment (different artifact per character, shared palette/grain), and only the treated WebP is committed. Official art is never used as hero/decoration. The fair-use/DMCA trade-off was explained to the user and they chose it.
- **Fact-checking:** same discipline as the Red Rising builds (the field-report lines on the opening only state verified facts). Canon-only memorial: no invented soldier names; unnamed rows read "name not recorded".

## Running playwright-cli

```bash
npm install -g @playwright/cli@latest
python3 -m http.server 8765 &          # file:// URLs are blocked by default
playwright-cli open http://localhost:8765/Iman_Kasim_Portfolio.html
playwright-cli screenshot
```

`.playwright/cli.config.json` selects Chromium. In Claude Code on the web, the bundled Playwright expects a newer Chromium than the one pre-installed, so also run `export PLAYWRIGHT_MCP_EXECUTABLE_PATH=/opt/pw-browsers/chromium` (don't run `playwright install`). Locally, run `playwright-cli install-browser chromium` once instead.
